### 1. 「用範圍 PUT 補行」誤吃相鄰行——本專案同類失誤三度（本輪最重）

`PUT N.=M` 語意是「取代 N–M 那幾行」，不是「往 N 後插入」；純增添誤用它＝被點名的行無聲消失。本輪踩中 mock `mockTickets` seed 的 `category_label`／`location_label` 八處被 id 欄蓋掉——daily-report 的 mock 組裝靠 `t.location_label` 拼時間軸列 → 預覽「大廳／停車場」變空 → CI e2e `toContain("大廳")` 連兩輪紅，本地 178 測＋jsdom 煙霧全綠抓不到。前兩度同因：dailyReport `location_label`、boundary `it(...)` 表頭。

**判歸「工具用錯」非「專案慣例」——reviewer 規則檔不該收；修法＝建快速抓回＋施工慣例一句。**

- **Automated check（機械失誤正解）**：本 bug 有本地快速訊號＝jsdom 開 `#/stats` → 報告 tab → 預覽 `toContain("大廳"/"停車場")`。現行 e2e `daily-report.spec.js` 已釘這斷言（是它救回 CI），但它只在 deploy 後跑（約 130 秒＋已上線）；挪一份等價 jsdom 測進 `test:local`＝pre-commit 的 5 秒抓紅。**建議落地：建此 jsdom 行為測（經真實 UI 組裝、非源碼 grep），補進 `tests/panel-load.test.ts` 或新檔。**
- **施工慣例（判斷類、一句即可）**：增添用 gap PUT（`>N:`／`<N:`），只有取代才用 `N.=M`／`N*`；要動的行沒出現在最近的 `read` 顯示＝先顯示再寫；批次編輯 commit 前 `git diff` 看全量負號行、不靠關鍵字過濾（本輪 diff 我只 grep 了 id／filterByCat 就放行，負號裡的 label 刪除線是漏網之魚）。

### 2. bootMock 沒掛 `mockApi`（information access）

`mockApi` 與 `mockTickets` 等是頂層 `function`／`const`，落在 isolated context 不落 `window`——smoke 想 `win.eval('mockApi("/api/stats/daily-report?...")')` 直組裝即 `not a function`，只能繞 `#/stats` 面板真實路由。**建議**：harness `bootMock` eval 字串尾補 `window.mockApi = mockApi;`（同 `loadInto` 掛 window 的既有慣例），日後 mock 直測免繞 UI。本次靠真實路由繞過、未擋下施工，屬可補資訊面。

### 3. 沙箱 `gh run view --log-failed` 要 `safe.directory`（tool economy）

`gh run view 38114997354 --log-failed` 直接被 gh 內部 git 擋下 `detected dubious ownership in repository at '/work'`——因為 gh 需要 repo 錨點。免污染設定的解＝`export GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=safe.directory GIT_CONFIG_VALUE_0=/work` 再跑 gh（比 `gh api .../logs` 省一大截 token，日誌已按失敗 job 過濾）。補進 CLAUDE.md 環境備註一語即可。
