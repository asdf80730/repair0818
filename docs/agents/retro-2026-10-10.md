## Findings

### 1. e2e  locator 斷言的兩個假紅模式（automated check）

本輪實測到兩種，未來同一模式會再遇：

- **非 await 的 locator 斷言**：`expect(page.locator(...)).toBeVisible()` 不帶 `await` 時，test 結束即關 session，斷言拿到 `Received: undefined` 假紅（本輪 `.insert-panel` 案）。值斷言（`expect(str).toContain(...)`）同步、可不帶 await；**locator 斷言必須帶**。
- **去編號後 `getByText` 雙命中**：列表標題去 `#NNNN` 後只剩 `getByText("電梯－編號")` 級字串會命中多卡（`電梯－停車場 (53 天)`／`(0 天)`）→ strict violation。標題斷言帶天數（`(53 天)`）保唯一，或改 `locator(...).filter({ hasText }).first()`。

可入 pre-commit 的机械檢查（對 #1）：

```
grep -rnE "^ *expect\(" e2e/*.spec.js   # 列非 await 斷言行，逐行判：locator 版需補 await
```

（值斷言行同步可留；只有 `expect(page`／`expect(locator`／`expect(ta)` 等 locator 版是紅點。）

### 2. jsdom 探測的兩個實測點（information access；補進 `docs/agents/jsdom-harness.md`）

- `new JSDOM(html, opts)` 實例的 `.document` 為 `undefined`；用 `w.window.document`。
- 多檔字串一次 `win.eval(te + "\n" + app)` 會令尾段宣告失聯（`boot is not a function`）；**逐檔分開 eval**（`win.eval(te); win.eval(pre); win.eval(app);`）即可，各 eval 內共享同一 realm。
