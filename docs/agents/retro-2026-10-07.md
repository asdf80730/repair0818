## Findings

### 1. Issue-list call dumps verbose nested JSON (tool economy)
The `gh` path (`docs/agents/issue-tracker.md` line 9) already projects with `--jq`. The no-`gh` curl fallback (§「無 gh 時的等價 curl」) returns the raw payload: for 6 issues that is ~7 KB, dominated by the per-issue repeated `user` / `labels` objects. Add a trailing projection to the 列票 line so the fallback is as lean as the `gh` path:

```
... /issues?state=open&labels=<label> | jq -c \
  '[.[] | {n:.number, t:.title, s:.state, labels:[.labels[].name], blocked_by:.issue_dependencies_summary.blocked_by}]'
```

The fields above are exactly what the frontier query needs (number/title/labels/blocked_by).

### 2. Seed transform rules lack an always-reachable pointer (navigation)
`docs/SPEC.md` §2.3 carries the seed **value sets** (categories/locations/vendors) but not the **Excel→SQL transform** that the seed depends on. When map #15 closes, those rules live only in the closed ticket body. Promote the four facts that had to be reverse-engineered from `initial-data/001_excel_tickets.sql` into §2.3 as compact lines:

- 狀態 → 四值：已完成／售服系統已結案→`done`；已報修→`in_progress`（逐筆：F 欄廠商非空，空則 `open`）；需二次複查／已報價待修復→`in_progress`；已報修等報價／未報修／(空)→`open`；取消報修／重複報修→`void`。
- 位置：單字母 A–F→`三期{L}棟`、G–K→`四期{L}棟`；`公共區域`／`一樓外圍`／`B1·B2·B3地下室公設` 原樣。
- 日期：Excel serial → ISO，1900 曆，epoch `1899-12-30`，形 `YYYY-MM-DDT00:00:00.000Z`。
- `in_progress` 案另記 `amount=1`、`amount_at=`報修日；其餘 `amount`／`amount_at`＝NULL。`closed_by`＝1。

This makes the xlsx→SQL generator deterministic from one `SPEC.md` read (the 49.9 MB xlsx exceeds the auto-read cap, so each run drives it with a python script anyway).
