# v1.1.16 變更計畫（草案）——「案件動態訊息框 + 訊息模板系統」簡化

> **狀態**：🟡 業主討論草稿，尚未拍板。本文僅為清點與簡化方向，**不觸碼、不改規格**。

## 0. 功能定位回顧（v1.1.15 F1–F12）

這組功能在 v1.1.15 定稿（業主 2026-08-23 拍板全部照做），核心是兩塊：

| 區塊 | 目的 | 決策碼 |
|---|---|---|
| **案件動態訊息框** | 統計頁選日期 + 類別 → 即時渲染當日消息 → 一鍵複製到剪貼簿，保全直接貼群組 | F1 / F2 / F3 / F5 |
| **訊息模板系統** | manager/admin 在獨立頁維護「報告模板 / 無更新模板」的文字與變數 | F6 / F7 / F8 / G7 |

兩者透過 `templateEngine.render(body, ctx)` 串起來：**後端回傳純資料 + 模板 body，前端用模板引擎渲染成純文字再複製。**

## 2. 複雜度來源（為什麼感覺太重）

| # | 複雜度來源 | 說明 | 影響 |
|---|---|---|---|
| C1 | **模板引擎雙份維護** | `src/lib/templateEngine.ts`（server/ESM/vitest）與 `public/templateEngine.js`（browser/IIFE）**同一邏輯拆兩份**，任一變更要同步兩處 | 維護負擔 + 容易不同步 |
| C2 | **引擎功能過載** | 支援巢狀 `{{#each}}`、變數堆疊查找回回、4 種自動變數、缺值容錯…但保全日常只要「列出今天的變更」 | 對目標場景屬超額設計 |
| C3 | **前端管理頁過於完整** | F7 頁有雙層下拉變數插入、點擊插入面板、textarea IntelliSense、即時預覽、G7 出廠重置 — 像個小型編輯器 | 保全/管委會用不到這麼重 |
| C4 | **mock fixture 散落重複** | `app.js` 內 F10 mock（line 46~59）與 F7 內建 fixture（line 1694）**硬编码两份模板 body**，且與 seed 文字一致 | 三處重複、易脫節 |
| C5 | **資料層級過深** | daily-report 回傳 `new_tickets` / `existing_tickets` / `updates_today` 等多組陣列 + template.body，全部丟給前端渲染 | 若後端直接吐成品文字可省掉整條渲染鏈 |
| C6 | **模板管理走關聯表** | 模板复用 `options` + `option_categories` 類別關聯、label 二態、全域/類別優先排序 | 只有 report/empty 兩套預設時，關聯與「不做全部」規則偏重 |

## 3. 簡化方向提案（供業主選擇，待拍板）

> ⚠️ 依 CLAUDE.md 規則 12：以下為**建議**，未經明確指示前不改規格、不觸碼。

### 方案 A —「後端直接吐成品」（瘦身幅度最大，推薦優先評估）
- daily-report **後端直接渲染最終文字**回 `message` 欄位；前端只負責「複製貼上」這一步。
- **可刪除**：`public/templateEngine.js`、`src/lib/templateEngine.ts`、`tests/templateEngine.test.ts`，以及 app.js 的渲染/預覽區塊（textarea 即時預覽可省）。
- 模板仍是 `options.body` 純文字字串；後端用極簡替換（甚至固定格式）即可。
- 效果：砍掉雙份引擎 + 前端編輯器級預覽，留下一條最短路徑：**選日期/類別 → 貼上**。

### 方案 B —「保留引擎、砍管理頁」（中等瘦身）
- 保留 templateEngine 與 daily-report，只簡化 F7 管理頁：移除變數插入面板 / IntelliSense，改 CLAUDE.md 既定做法「後台直接改資料庫」。
- 收掉重複 mock fixture（line 46~59 與 line 1694 合為一份）。

### 方案 C —「最小改動」
- 僅修 bug、抽離重複 fixture，引擎與管理頁原樣保留。
