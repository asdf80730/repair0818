### F. 統計頁「案件動態」訊息框（2026-08-23 業主需求）

**目標**：保全每天對委員發 LINE 群組報告「今天有變更/新增/完成的案件」。時間口徑為**伺服器台灣時區**任選一天（不限定今日）。訊息依類別切分（每個類別一份），下拉式方塊切換。長度要短（LINE 群組）。新案件詳細、舊案件簡提，附 ticketNo（如 `#0007`）或詳情連結（**登入後才看得到的詳情連結**＝`{baseUrl}/#/ticket/{id}`，**非 share 公開連結**）。訊息格式可自訂（**變數模板**），無更新時顯示**自訂空態訊息**。

#### F1. 後端 — 新增 `GET /api/stats/daily-report`

- **檔案**：`src/routes/stats.ts`
- **權限**：套 `requireAuth()`，三角色皆可（同 `/summary`）
- **Query**：`category_id=N`（**必填**，無 category 不回；不做「全部」避免訊息過長）
- **時間計算**：新增 `src/lib/time.ts → taipeiDayRangeUtc(date?)` 回 `{startMs, endMs}` = 當天 00:00:00.000 ~ 23:59:59.999 的 UTC ISO；訊息內 `HH:MM` 用 `Intl.DateTimeFormat('zh-TW', {hour:'2-digit', minute:'2-digit', hour12:false, timeZone:'Asia/Taipei'})` 轉
- **回應結構**：
```jsonc
{
  "date": "2026-08-23",                      // 台灣今天
  "category_id": 1,
  "category_label": "水電",
  "total_count": 5,                            // 訊息標題用
  "new_tickets": [{
    "id": 7, "title": "水電－頂樓 #0007",
    "location_label": "頂樓",
    "description": "水泵故障",
    "creator_name": "王小明",
    "created_at": "2026-08-23T...",
    "status": "open",
    "detail_url": "https://repair-system-4re.pages.dev/#/ticket/7"
  }],
  "existing_tickets": [{
    "id": 3, "title": "水電－大廳 #0003",
    "current_status": "in_progress",
    "status_label": "已發包",
    "updates_today": [{                        // 該案件今天所有 update（最多 3 筆）
      "kind": "status", "status": "in_progress",
      "actor_name": "王小明", "time": "10:23",
      "note": null, "amount": 5000
    }]
  }]
}
```
- **SQL 策略**（避免 N+1）：
  1. **新建**：`SELECT ... FROM tickets t JOIN users u ON u.id=t.created_by WHERE t.category_id=? AND t.created_at BETWEEN start AND end`，JOIN 拿 creator_name
  2. **既有**：`WHERE category_id=? AND last_activity_at BETWEEN start AND end AND id NOT IN (新建 ids)`
  3. **updates_today**：用 `SELECT u.*, usr.display_name FROM ticket_updates u JOIN users usr ON usr.id=u.user_id WHERE u.ticket_id IN (既存 ids) AND u.created_at BETWEEN start AND end ORDER BY u.created_at DESC` → 應用層按 ticket_id 分組 + slice(0,3)
- **detail_url**：用 `env.BASE_URL`（沒設 fallback `https://repair-system-4re.pages.dev`） + `/#/ticket/${id}`；不走 share_token（業主明確要登入後才看得到的連結）
- **契約變更**：新增 endpoint，**不影響**既有 `/summary`、`/amount-by-category`——純加

#### F5. 訊息變數模板系統（業主決策 2026-08-23）

業主可在「訊息模板管理」頁（manager/admin）**自訂訊息模板**，用 `{{變數名}}` 塞資料。

**可用變數（固定，與 API 回應欄位一一對應）**：

| 變數 | 來源 | 範例 |
|---|---|---|
| `{{date}}` | API 回傳 | `2026-08-23` |
| `{{category_label}}` | API 回傳 | `水電` |
| `{{total_count}}` | API 回傳 | `5` |
| `{{new_count}}` | 計算 | `2` |
| `{{existing_count}}` | 計算 | `3` |
| `{{new_tickets}}` | 渲染：迴圈區段（見下方「區段語法」） | （多行） |
| `{{existing_tickets}}` | 渲染：迴圈區段 | （多行） |

**迴圈區段語法**（**極簡**，不引入 jinja/template engine）：
```
{{#each new_tickets}}
  {{序}}. {{title}}
     {{description}}
     詳情：{{detail_url}}
{{/each}}
```
- `{{#each X}}...{{/each}}` 區段會對陣列每筆展開
- 區段內可用該筆的所有欄位（id, title, location_label, description, creator_name, created_at, status, detail_url）
- `{{existing_tickets}}` 區段內額外可用 `{{#each updates}}...{{/each}}` 巢狀迴圈，每筆 update 有 time / actor_name / note / status / amount / kind

**預設模板**（**全預設寫死**，業主不編輯也能用）：
```
📅 {{date}} {{category_label}}案件動態（共 {{total_count}} 件）

{{#if new_count>0}}🆕 新建案件（{{new_count}}）：
{{#each new_tickets}}
{{序}}. {{title}}
   {{description}}{{creator_name}} {{created_at_time}}
   詳情：{{detail_url}}
{{/each}}{{/if}}

{{#if existing_count>0}}📝 既有案件更新（{{existing_count}}）：
{{#each existing_tickets}}
{{序}}. {{title}} → {{status_label}}
{{#each updates_today}}
   {{time}} {{actor_name}}：{{note_or_status}}{{amount_text}}
{{/each}}{{/each}}{{/if}}
```

**注意**：上面的 `{{#if X>0}}` 條件語法是「極簡示意」，實際實作 v1.1.15 只支援 `{{#each}}...{{/each}}` 一種控制語法，**不做 if 條件**（太複雜）。改用「空陣列不渲染」自動處理：若 `new_count===0`，`{{#each new_tickets}}...{{/each}}` 區段整段消失。

#### F6. 後端 — 模板 CRUD

- **新 migration 0010**：
```sql
CREATE TABLE message_templates (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,                 -- 模板名稱（如「簡潔」「詳細」）
  type        TEXT NOT NULL CHECK (type IN ('report','empty')),
                                                 -- report = 案件動態主模板；empty = 無更新訊息
  body        TEXT NOT NULL,                 -- 模板內容（含 {{變數}} 與 {{#each}}）
  active      INTEGER NOT NULL DEFAULT 0,    -- 啟用標記（每 type 同時間只可 1 個 active）
  is_default  INTEGER NOT NULL DEFAULT 0,    -- 系統預設模板，UI 顯示「（預設）」不可刪
  created_by  INTEGER NOT NULL REFERENCES users(id),
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE UNIQUE INDEX idx_message_templates_active
  ON message_templates(type, active) WHERE active = 1;  -- 每 type 同時間只 1 個啟用
```
- **路由**（`src/routes/messageTemplates.ts`）：
  - `GET /api/message-templates` — 三角色皆可讀（統計頁要用）
  - `GET /api/message-templates/:id` — 三角色皆可讀
  - `POST /api/message-templates` — manager/admin，建立（初始 active=0）
  - `PUT /api/message-templates/:id` — manager/admin，編輯 body/name
  - `POST /api/message-templates/:id/activate` — manager/admin，啟用（自動取消同 type 其他 active，transaction 處理）
  - `DELETE /api/message-templates/:id` — manager/admin，僅可刪 `is_default=0` 的
- **seed 預設**（migration 0010 內 `INSERT`）：type='report' 與 type='empty' 各塞一個 `is_default=1, active=1` 的預設模板（body 即 F5 的預設內容）
- **`daily-report` 改為**：原本的內建組訊息邏輯**刪除**，改為回傳純資料 + **前端**用模板渲染（避免後端組兩次）
  - 後端仍可加 `?template_id=N`（缺省用 active 的 report 模板），但**不渲染**，只回 `template.body` 讓前端用，**或**前端另呼叫 `/api/message-templates` 抓 active（兩種都可，前者省一次 roundtrip → 推薦）

#### F8. 前端 — 模板渲染引擎（純函式，可單測）

**新檔**：`public/templateEngine.js`（或合併進 app.js，**新檔較好測**）：

```js
// 變數替換：{{key}} → 從 ctx 物件取值
// 區段展開：{{#each arr}}...{{/each}} → 對 arr 每筆展開
// 巢狀支援：{{#each outer}}...{{#each inner}}...{{/each}}...{{/each}}
// 變數點查找：先查 ctx 本身，找不到查當前 each 迴圈的 item
// 缺值：保留 {{key}} 字面（讓使用者知道漏變數）；額外 console.warn

export function render(template, ctx) { /* ... */ }
```

**輸出邊界**：
- `{{序}}` 在 each 區段內自動填 `1, 2, 3...`（不是 ctx 欄位，是 engine 自動加的計數器）
- `{{created_at_time}}` 不是直接欄位，是 `created_at` ISO 轉 `HH:MM`（engine 自動轉，台灣時區）
- `{{note_or_status}}` 在 each updates 內：`kind='comment'` 用 `note`，否則組「狀態：{status_label}」
- `{{amount_text}}` 在 each updates 內：amount 非空時拼「（$5,000）」

**單元測試**（`tests/templateEngine.test.ts`）：
- 簡單變數替換
- each 區段展開（含空陣列）
- 巢狀 each
- 缺變數保留 `{{key}}`
- 特殊字元 escape（用戶模板可能含 `<` `>` `&`，**不做 HTML escape**，訊息是純文字）

#### 風險與卡點

1. **訊息長度**：LINE 群組單則上限 5000 字元；模板內建每筆 update 最多 3 筆的限制由模板作者決定（不再由程式強制），需在預設模板註解提醒
2. **跨午夜 created_at**：指定 `date=2026-08-23` 時，台灣 02:00 建單（UTC 前日 18:00）算 2026-08-23（**符合語意**：保全在 8/23 下班前看 8/23 整天）→ 後端 `taipeiDayRangeUtc('2026-08-23')` 必須正確處理
3. **多次結案的同案件**：done→reopen→再 done 在指定日內 updates 都列，模板作者需自己用 `{{#each}}` 控制
4. **`last_activity_at` 可靠性**：每次 create update/void/reopen 都會更新，但施工前需查證寫入路徑全數更新
5. **模板引擎安全性**：用戶自訂模板含 `{{}}` 必須嚴格解析，不可誤執行為 JS；**純字串替換** 不會有此風險
6. **active 唯一性**：SQLite `UNIQUE INDEX ... WHERE active=1` 是部分索引，D1 支援，但**POST `/activate` 仍須 transaction**（UPDATE active=0 + UPDATE active=1 兩步非原子會有競態）
7. **預設模板保護**：`is_default=1` 不允許刪除（前端禁用按鈕，後端 403 雙重防護）
